## 3. Data flow and invariants

External bearer stays request-local. Maintained verifier creates verified issuer/subject/client facts; host authorization resolves its internal principal and grants exact requested tenant quad, ledger scope, action and body-specific actor/delegation. Boundary rejects foreign permits and empty principals. Authorized context creates an opaque replay partition; raw bearer/provider claims never enter partition/log/storage. The same authorized context/body must reach actual handler and both replay reserve/record. Each retry repeats current token/grant/delegation checks before cached receipt disclosure.

Required future invariants: external mode never falls back; authenticated tenant scope and canonical ledger used consistently for actual locks/repository/hash/publication, not merely cache; canonical ledger scope globally unique or host mapping refuses ambiguity. Trusted partition uses collision-safe encoding and includes internal principal, admitted full tuple and route. ScopeAction matches actual effect: head Read+Administer, append includes its initial publication, pinned/registries Read. Borrowed Append body is parsed once under an explicit size bound and retained unchanged, so host delegation checks cannot authorize one body and execute another. Trellis remains ignorant of WOS actor vocabulary.

Provider snapshot contains exact signed events, scope/seal/high-water/generation/attempt identity; consumer owns original evidence and associations. Required bytes fixed before first immutable publication, repeated generation returns same bytes, unavailable source rejects. `export_attempt_id` does not include evidence bytes, so incomplete-first/complete-later under one identity is forbidden. Existing immutable storage detects byte conflicts but does not supply missing evidence authority. Full Core+composed validation precedes publication. Reader-specific variants need separate identity design; no new variant is admitted here. Existing append persists before publication (`append.rs:217–221`): a publication refusal may leave a durable event and require exact retry recovery; no atomic append/publication claim is made.
