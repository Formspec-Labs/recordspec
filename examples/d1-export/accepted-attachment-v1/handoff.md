# Accepted attachment preparation and signature catalog encoder

The shared Trellis libraries now admit a closed accepted-attachment descriptor and prepare its existing ADR-0072 binding. Preparation checks exact original bytes, separately hashes supplied ciphertext, retains occurrence and logical-slot identities, checks the supplied prefix, and refuses stale replacements. Ciphertext is borrowed. Maintained CBOR, hash and event parsing helpers supply these checks.

The caller must supply trusted Source acceptance evidence and an already trusted, committed prefix. Preparation does not authenticate that evidence, check signatures, prove a live head is complete, or prove encryption. Selecting the latest same-slot binding is the selected Source policy. The descriptor and scope participate in the preparation replay digest; a future event author must also retain complete protected-carriage metadata in its replay identity.

The new operation is deliberately absent from the ordinary append router: that path cannot yet construct its required extensions and protected carriage. No event was authored or appended. The next required input is the maintained protector's actual KeyBag and payload decoding metadata; empty keys or invented ciphertext framing cannot substitute for it.

The qualified `062` signature encoder and dependency manifest were copied into `trellis-verify-wos`, and its public export was adapted to the current library. The encoder pin is `1ac48dd38b7ebe3a783a5bfb68b951a7e4a0cdfb8ddb73d3339873fc43549c49`. The isolated export materializer requires a baseline absent from this shared checkout and was not copied. This is library adoption, not complete export wiring.

Validation: the final offline locked run passed 12 attachment tests, 9 admission library tests and 63 verifier library tests, including the six encoder tests. Tests cover closed admission, ordinary route refusal, original/ciphertext identity, finite limits, descriptor replay changes, prior identity and slot checks, latest replacement selection, broken links, and the maintained append018 canonical fixture. Neutral unsigned history fixtures establish structural checks only. Independent GPT-6.1-sol medium code and architecture reviews approved this bounded slice; both reviews were static. The code reviewer rechecked the final chained tests and reported no remaining actionable finding.

`qualification.json` contains exact source pins and operation limits. Logs retain the initial compile failure, genuine ordinary-route RED, and subsequent GREEN runs. The Cargo lock diff adds dependency edges; its pre-existing `stack-common-typeid` edge was preserved. Native checks used one build job and released both locks after confirming the owned process group was absent. No live service or repository data was changed by these checks.
